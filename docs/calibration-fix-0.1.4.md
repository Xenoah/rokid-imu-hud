# 0.1.4：OS姿勢の変化で校正が繰り返される問題

> 履歴：0.1.4時点の記録です。[0.1.5](calibration-fix-0.1.5.md)では利用者の依頼により、10秒の判定緩和と15秒の暫定開始を追加しました。以下の「強制開始なし」は旧仕様です。

更新日：2026-09-19 UTC。成果物：`dist/RokidHUD-0.1.4-debug.apk`、versionCode 5。配布済み0.1.0〜0.1.3と同じデバッグ署名です。

## 動画で確認できたこと

ユーザー提供の約42秒の動画を確認しました。前半の起動後から最後まで、校正完了の表示には進んでいません。

| 動画内の時刻（概数） | 表示 |
| --- | --- |
| 9秒 | `LAST: ATTITUDE CHANGED`、ACC 0.99G、GYRO 5.00°/s、POSE 1.9°、MEAN 4.73°/s |
| 15秒 | `WAITING FOR ATTITUDE`、GYRO 4.62°/s、POSE 0.4° |
| 21秒 | `CALIBRATION WAIT`、`LAST: ATTITUDE CHANGED`、POSE 0.1° |
| 27秒 | 向きを変えた後も待機。GYRO 5.61°/s、POSE 0.8° |
| 33秒 | `WAITING FOR ATTITUDE`、GYRO 4.05°/s、POSE 0.4° |
| 39秒 | `LAST: ROTATION DETECTED`、GYRO 4.06°/s、POSE 1.8° |

加速度・ジャイロは両方ともおおむね247Hz、姿勢源は `OS QUAT` と表示されています。28〜36秒付近を細かく確認すると、POSEが2°へ近づいては小さな値に戻っています。

これはOS姿勢の変化によって校正窓が繰り返し取り直されるコード経路と一致します。ただし映像から、実際の頭部回転、ジャイロのバイアス、OS姿勢推定のドリフトを分離することはできません。生IMUデータは受領しておらず、以下は画面の数値を参考にした模擬試験です。動画そのものはソースZIPに含めません。

## 原因と変更

0.1.3ではOS Quaternionが開始姿勢から2°変化すると、集計中の加速度・ジャイロも直ちに破棄していました。例えばOS姿勢が毎秒4.5°ずれる場合、必要な1秒間の集計を終える前に毎回リセットされます。また、自前融合側でも未校正ジャイロの平均を小さくする条件が先にあるため、一定のオフセットをバイアスとして推定する段階へ進めませんでした。

0.1.4では次の順で校正します。

1. 加速度・ジャイロを約1秒集計。OS姿勢の変化だけでは生データの集計を消しません。
2. 生加速度の大きさ・分散と、50ms時定数で平滑化した加速度方向の変化を検査。ジャイロの単発値・平均・分散、入力の鮮度も検査します。
3. 生データの条件を満たした時点で、OS姿勢の変化が2°を超えていれば、その実行セッションではOS姿勢を棄却します。OS姿勢から求めた残留ジャイロバイアスが0.10rad/sを超える場合も同じです。
4. Mahony方式の自前融合に切り替え、約1秒集計し直します。静止を前提として、安定した生ジャイロ平均をバイアスとして推定します。絶対値の上限は0.15rad/sです。
5. 合格後に姿勢基準・G基準・フィルタ・Peakを初期化し、`READY` または `RECENTERED` を表示します。

安定したOS姿勢は引き続き優先します。不安定と判断した姿勢源は同じ実行中に復活させず、世界座標の切替時は必ず校正し直します。生IMUが連続して安定していれば、切替を含めて約2秒の経路です。経過時間だけで強制的にREADYへ進める処理はありません。

150msを超えるセンサー欠落は静止観測時間へ数えません。ジャイロ分散の自前融合側の目安は1軸0.035rad/sに変更し、小さな頭の揺れも扱えるようにしています。すべての係数は `Config.java` にあります。

## 静止が必要な理由と限界

**6軸IMUだけでは、一定速度のYaw回転と一定のジャイロオフセットを完全には区別できません。** OS姿勢が同じIMUから作られる場合、それも独立した真値にはなりません。今回の自前校正は `KEEP HEAD STILL` に従って静止していることを前提にします。回転中に校正すると、一定の回転をバイアスに取り込む場合があります。

したがって、0.1.3の「一定の生角速度を拒否する」2件の試験は、0.1.4ではこの観測不能性と静止前提を確認する試験へ変更しています。以前とまったく同じ運動拒否性能を維持したという意味での39件合格ではありません。重力方向が変わる傾斜、大きな角速度、持続振動、欠測の検査は継続しています。持続並進加速度と重力の区別、単一姿勢からの全軸加速度バイアスの同定にも限界があります。

## 検証

新しい7ケースを、配布した0.1.3の演算ソースと0.1.4で比較しました。

| 模擬入力 | 0.1.3 | 0.1.4 |
| --- | --- | --- |
| OS姿勢が4.5°/sでずれる。198/247Hz、Pitch/Yaw、Pitch側は0.32°・2Hzの微動も付加 | 完了できない | 3秒未満で自前融合へ復帰。その後60秒相当の静止も確認 |
| OS姿勢なし、静止ジャイロオフセット4.5°/s | 完了できない | バイアスを推定して完了 |
| 本当に4.5°/sでPitch回転 | 校正を拒否 | 生加速度方向の変化により拒否 |
| 大きな動きを止めた後、OS姿勢だけがずれる | 復帰できない | 再起動せず復帰 |
| 自前融合で再校正、バイアス更新、Peakとフィルタ初期化 | 初回校正できない | 完了 |
| 校正の途中で加速度入力が1秒欠ける | 欠測区間を含めて完了してしまう | 新たな連続観測を待って完了 |
| OS姿勢は安定、ジャイロオフセット6.2°/s | OS側バイアス上限で繰り返し待機 | 自前校正の上限内で復帰 |

旧版は1件合格・6件失敗、修正版は7件合格。全体は39件合格です。記録は `artifacts/calibration-before-0.1.4.txt` と `artifacts/core-test-results.txt`。Androidコンパイル、DEX変換、署名・整列、11項目のAPK内部検査も完了しています。**0.1.4のRokid実機／エミュレーター実行は未確認です。**

## インストールと診断

上書きインストールし、起動後は頭を静止させて2〜3秒ほど待ってください。

```sh
adb install -r dist/RokidHUD-0.1.4-debug.apk
adb shell am start -n dev.xenoah.rokidhud/dev.xenoah.hud.MainActivity
```

待機画面は `POSE`＝OS姿勢の最大変化、`TILT`＝生加速度方向の最大変化、`GYRO MEAN`＝生ジャイロ平均の大きさを別々に表示します。`OS UNSTABLE - IMU CAL` は自前融合への切替理由です。OS源を使わない間、POSEは `--`。`WAITING FOR ATTITUDE` は姿勢入力が戻れば集計表示へ更新します。

任意CSVに `cal_raw_tilt_deg` を追加し、全35列です。実装の書式をJVMで実行して列数を照合しました。CSVは10Hzの診断用で、全IMUサンプルの記録ではありません。
