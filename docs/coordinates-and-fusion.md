# 座標・姿勢融合・重力補償

## 座標の定義

| 座標系 | 正方向 |
| --- | --- |
| デバイスD | X＝右、Y＝上、Z＝装着者側。視線前方は−Z |
| OS Quaternionの世界W | Androidの世界座標。重力に対応する静止加速度は+Z方向 |
| 自前融合の世界W | 起動時の任意Yawをもつ右手系。静止加速度は+Y方向 |
| RESET基準R | 校正完了時のデバイスDと同じ向き。その後は固定 |

世界WはOS入力と自前融合で異なるため、入力方式を切り替えた場合は必ず再校正します。すべてQuaternionはHamilton方式、成分順は(w,x,y,z)。`q` はD→Wの能動回転です。Android Rotation Vector入力の並び(x,y,z,w)は入力部で変換します。

## Gメーター

`aD`＝SensorManager加速度、`bD`＝校正したデバイス軸のバイアス、`q0`＝RESET時のD→W姿勢、`gW`＝静止時に重力によって観測される加速度ベクトル。

```text
aW = rotate(q, aD - bD) - gW
aR = rotate(inverse(q0), aW)
LAT_G  = +aR.x / 9.80665
LONG_G = -aR.z / 9.80665
```

バイアスはデバイスに固定されているため回転前に除去します。世界座標やRESET座標の一定オフセットとして引くと、頭を傾けた際に誤差になるためです。

LPFは実際のサンプル間隔dtを使う1次指数フィルタです。

```text
alpha = 1 - exp(-2*pi*G_FILTER_CUTOFF_HZ*dt)
y = y + alpha*(x-y)
PEAK = max(PEAK, sqrt(filtered_LAT² + filtered_LONG²))
```

標準fc=4Hzでは時定数約39.8ms、90%到達約91.6msです。描画や姿勢までこのLPFを通しません。長いサンプル欠落後は古いLPF状態を引きずらず再初期化します。Gメーターは円周外へ出ないようドット位置を制限しますが、計測数値を±2Gに切り詰めません。

PEAKはフィルタ後の平面加速度のピークです。生の3軸合成G、重力込みのG、各軸別のピークではありません。

## Pitch / RollとYawの独立性

姿勢から現在のデバイス座標での世界上方向 `uD = inverse(q) * worldUp` を求めます。

```text
pitchAbs = atan2(-uD.z, sqrt(uD.x² + uD.y²))
rollAbs  = atan2(-uD.x, uD.y)
pitchHUD = pitchAbs - pitchAbs_at_reset
rollHUD  = wrap180(rollAbs - rollAbs_at_reset)
```

これにより、上を向くとPitch正、右に傾けるとRoll正。重力まわりのYawが変わってもPitch/Rollは変わりません。傾いた状態でRESETしても同じ性質を保ちます。**完全な相対Euler角を表示する実装ではなく、重力基準の傾斜角にゼロ点オフセットを適用**しています。G演算には省略しないQuaternion変換を使用します。

画面の機体マーカーは固定。水平線の座標系を `-rollHUD` 回転し、姿勢座標内で `pitchHUD × 3.1px/deg` 下へずらします。正のPitchでは水平線が下がり、右Rollでは水平線右端が上がります。遠近投影による厳密な視野角校正ではなく、角度目盛のHUDです。

## センサーフュージョン

1. 起動時にOSのGAME_ROTATION_VECTORを探し、無ければROTATION_VECTORを探します。GAMEを優先するのはPitch/Rollに地磁気方位を必要としないためです。
2. 登録失敗・未搭載ならジャイロ＋加速度へ。OS姿勢が150ms以上停止、またはUNRELIABLEが2秒以上続いた場合も自前融合へ切り替えます。通常の監視には起動直後2秒の猶予を置きます。校正中は加速度イベント側でもOS姿勢の鮮度を確認し、150msを超えて更新されなければ自前融合へ切り替えます。0.1.4では生IMUの条件を満たした窓でOS姿勢が2°を超えて変化する場合、またはOS側の推定ジャイロバイアスが0.10rad/sを超える場合も切り替えます。また、静止窓の加速度とOS姿勢から予測した重力の差が0.5m/s²を超える場合、整合しないOS姿勢をその実行セッションでは再使用せず、自前融合で校正し直します。
3. 自前融合はMahony方式の比例重力補正です。ジャイロから固定残留バイアスを引き、予測上方向と正規化加速度の外積を角速度へ加えます。Quaternionの更新は回転指数写像を使い、毎回正規化します。
4. 加速度の大きさが1Gから6%以上外れる場合、または重力方向とのずれが2.5°以上の場合は重力補正を止めます。大きな並進加速度を傾きへ誤変換しにくくするためです。
5. 積分型のバイアス適応は走行中の誤学習を避けるため使いません。gyro biasは静止校正で取得します。Yaw補正はありません。

ゲートは完全な静止／加速分類器ではありません。小さい持続加速度、温度ドリフト、ジャイロオフセット変化は残ります。重力方向との誤差がゲートを超えた場合は重力補正だけで復帰しないこともあるため、静止してRESETしてください。

## 時刻・スレッド

- センサー計算のdtはセンサー時刻の差。コールバック到着時刻や描画フレーム間隔から積分しません。
- 描画は `elapsedRealtimeNanos` とセンサー時刻を比較し、150msより古い値をライブ表示しません。
- 低頻度のOS姿勢の間を埋めるため、最後のOSサンプルから最大100msまで、校正済みジャイロでQuaternionを最新のセンサー時刻へ進めます。最新の角速度を一定とみなす短い外挿なので、急な角加速度・バッチ配送では誤差が残ります。OSサンプル受信時にはその姿勢を採用し直します。G計算時の姿勢と加速度の時刻差は最大30ms、外挿用ジャイロの時刻差も最大30msです。描画時刻までの予測や加速度の二重積分はありません。
- 単一のIMUスレッドがEngineを書き込み、短い同期区間でprimitiveだけをSnapshotへコピーします。描画側は独自のコピーを使います。
- `Vec3`、Quaternion、数値文字バッファ、Paint、軌跡配列を再利用します。OS内部のCanvasやSensorEvent実装まで無割り当てを保証するものではありません。
- 任意CSVは別のI/Oスレッドで10Hz。IMU全サンプルの無損失レコーダーではありません。

## 静止校正の窓（0.1.5）

以下は0〜10秒の通常校正の条件です。0.1.5では10秒で観測窓を0.5秒へ短縮し、加速度標準偏差の目安0.35m/s²、ジャイロ0.12rad/s、生加速度方向6°、加速度ノルム誤差1.0m/s²、単発ジャイロ0.60rad/sへ緩和します。最小サンプル数・入力鮮度・バイアス上限は維持します。

15秒で未完了なら、妥当な入力がある場合は既存バイアスを保持し、新しいバイアスを学習せずに加速度方向から暫定姿勢を作ります。初回の追加補正はゼロです。緩和・暫定開始は `APPROX` と表示します。センサー欠落／不正入力ではエラーで終了します。ソース切替や校正窓の消去は期限を延ばしません。詳細は [calibration-fix-0.1.5.md](calibration-fix-0.1.5.md)。

加速度とジャイロをそれぞれWelford法で集計し、毎サンプルのオブジェクト生成を避けています。両ストリームの開始時刻の遅い方から1秒以上、各20サンプル以上が必要です。OS姿勢がある場合は最低5姿勢サンプル・1秒以上の姿勢窓も要求します。OS姿勢の変化は生データ窓の早期消去理由にしません。

| 判定 | 条件 |
| --- | --- |
| 加速度の大きさ | 1Gからの差が0.6m/s²以下 |
| 加速度の分散 | 3軸合計が `3 × 0.12²` 以下 |
| 生加速度方向 | 時定数50msのEMA。最初の100msを待って基準を作り、以後の最大角度差が2°以内 |
| ジャイロ単発値 | 大きさ0.35rad/s以下 |
| ジャイロ早期平均 | 100ms・5サンプル以上で0.15rad/s以下。既に校正済みの自前融合経路では既存バイアスを引いた残差に適用 |
| ジャイロ分散 | OS経路は3軸合計 `3 × 0.075²` 以下、自前融合は `3 × 0.035²` 以下 |
| 入力鮮度 | 150msを超える加速度／ジャイロ欠落後は窓を取り直す |
| 加速度バイアス | 推定値の大きさ0.5m/s²以下 |

生データの条件を通過した後、OS姿勢を継続使用するか判断します。

- 窓内の全OS姿勢について、開始からの最大角度差が2°を超えていれば、そのセッションのOS姿勢を棄却し、自前融合へ切り替えて新たな1秒窓で校正します。qと−qは同じ姿勢です。
- OS姿勢を使える場合、隣接Quaternion間の最短相対回転ベクトルを加算し、窓の長さで割った平均角速度を生ジャイロ平均から引きます。残留バイアスが0.10rad/sを超える場合も自前校正へ切り替えます。小角度・短時間の近似であり、時間ずれによる誤差は残ります。
- 自前融合では静止を前提に生ジャイロ平均をバイアスとして取得します。最終的なバイアスの絶対値は0.15rad/s以下を要求します。既存バイアスがある場合も、この絶対上限は変わりません。
- OS経路で確定するときは最新OS姿勢と加速度の時刻差も30ms以内か確認します。20Hzの姿勢でも次の新しい姿勢を待って確定でき、毎周期窓を消去しません。
- 全条件を通過して初めてバイアスと基準姿勢を確定します。OS世界は上方向+Z、自前融合世界は+Yなので、切替時に旧基準を流用しません。

値は `Config.java` に分離しています。`GravityWindow` はOS姿勢や未校正ジャイロの積分結果を使いません。`POSE` と `TILT` の表示はそれぞれ独立したOS姿勢の変化と生加速度方向の変化です。ただし両方とも元のIMUに依存しており、独立した外部測定ではありません。

**静止は利用者が満たす必要のある前提です。** 6軸では一定Yawと一定ジャイロオフセットを区別できません。0.1.4は起動を妨げていた低い未校正角速度しきい値を緩和する一方、一定Yawを拒否できるという扱いをやめ、この制約を試験にも明示しました。持続並進加速度と重力の区別も不完全です。大きな動きや分散を検出できても、すべての運動を検出する保証にはなりません。

## 軸の変更

`AxisMap(x,y,z)` の各引数は元センサー軸を指定する±1..±3です。例えば(2,-1,3)は新X=旧Y、新Y=−旧X、新Z=旧Z。行列式+1の回転のみを受け付け、鏡映を拒否します。Quaternionも同じ座標変換へ対応させます。実機検証なしに符号を反転することは避けてください。
