# 装着中の校正判定の修正（0.1.3）

2026-09-19 UTC。ユーザー提供のRokid Glasses実機写真（10017.jpg、13:18表示）を受けた修正です。写真を同梱・加工してはいません。

## 実際に確認できたこと

画面には `CALIBRATION WAIT`、`LAST: ROTATION DETECTED`、ACC 0.99G、GYRO 3.69°/s、A 198Hz、G 198Hz、OS QUATが表示されています。アプリの起動と描画、センサー受信はできており、校正の途中で待機しています。

0.1.2は、100ms以上のジャイロ平均の大きさが0.045rad/s（約2.58°/s）を超えると窓を取り直すため、頭部の小さな揺れや残留オフセットで待機し続ける場合があります。ただし写真の3.69°/sは瞬間値です。生データがないので、その個体で動き・ノイズ・残留バイアスのどれが支配的かは確定していません。写真だけを根拠に軸や単位を変更していません。

## 変更内容

OS Quaternionがある場合は、1秒以上の窓の全姿勢サンプルで、最初からの角度差が2°以内か確認します。生ジャイロの平均だけでは棄却せず、小さな頭の揺れと有界の残留バイアスを許容します。ジャイロ平均から、隣接するOS Quaternionの相対回転で推定した平均角速度を引いてバイアスを求めます。実際のゆっくりした動きを、そのままバイアスとして引かないためです。

推定バイアス上限0.10rad/s、最大単発角速度0.35rad/s、加速度分散・重力整合・時刻鮮度の検査は残します。OS姿勢がない場合は、重力だけで持続Yawとバイアスを区別できないため、旧来の厳しい静止条件を維持します。時間切れだけでREADYを強制する処理はありません。

待機画面とログへ `POSE`（開始姿勢からの最大角度差、度）と `MEAN`（生ジャイロ平均の大きさ、度/秒）を追加しました。大きな回転、過大な推定バイアスも別の理由として表示します。

## インストールと確認

`RokidHUD-0.1.3-debug.apk` を上書きインストールし、起動後、頭を1〜2秒ほど静止させてください。配布済み0.1.0／0.1.1／0.1.2と同じ署名、versionCode 4です。

まだ待機する場合、理由・POSE・MEAN・ACC・GYRO・取得Hzが見える画面が次の切り分け材料になります。OSの姿勢もIMU由来で誤差があり、実回転とバイアスを完全に判別できる保証はありません。

今回のAPKはコンパイル、DEX、署名・整列、内部検査が完了しています。修正版0.1.3のRokid実機起動・校正完了は未確認です。
