# 静止校正の待機が終わらない問題への修正

2026-09-19 UTC。対象は0.1.1からの更新。報告は「Waiting for stillが終わらない」。実機ログや生データは提供されていないため、実際の端末でどの条件が起きたかは未確定です。

## 再現と変更

旧版では静止窓の各加速度イベントに対し、ジャイロ・姿勢との時刻差30ms以内を要求していました。OS姿勢だけが20Hz（50ms間隔）で届く場合、静止していても毎周期この条件に違反し、1秒の校正が終わりません。また、窓の最初の加速度サンプルとの差0.18m/s²・1軸あたり標準偏差0.07m/s²という条件では、静止ノイズでも繰り返し棄却されました。

模擬入力で以下の3件を再現しました。旧版の結果は `artifacts/calibration-before-0.1.2.txt`、修正後は `artifacts/core-test-results.txt` に保存しています。

| 入力 | 旧版 | 0.1.2 |
| --- | --- | --- |
| 姿勢20Hz、加速度・ジャイロ200Hz、静止 | 完了しない | OS姿勢を維持して完了 |
| 加速度ノイズ0.08m/s²/軸、静止 | 完了しない | 統計判定で完了 |
| OS姿勢の予測重力が実加速度と不整合 | バイアス検査を繰り返し失敗 | 自前融合に切替えて再校正 |

加速度とジャイロを独立した時間窓で集計する方式へ変更しました。動作時Gメーターの時刻差条件を静止校正から分離し、単発ノイズに依存するアンカー判定を取り除きました。OS姿勢が低頻度の場合、校正後の表示も途切れないよう、ジャイロで最大100msの短い姿勢外挿を行います。位置・速度の推定はありません。

校正失敗の理由、重力込みの加速度ノルム、角速度ノルム、加速度・ジャイロ実効Hzを待機画面に追加しました。CSVには理由と標準偏差、OS姿勢棄却の有無を追加し、通常Logcatでも約3秒ごとに診断情報を記録します。

## 更新後の使い方

`RokidHUD-0.1.2-debug.apk` を既存アプリへ上書きインストールし、起動後に頭を静止させてください。配布済み0.1.0／0.1.1と同じ署名で、versionCodeは3です。アンインストールは不要です。

待機が続く場合は、`CALIBRATION WAIT` の下の理由とACC/GYRO/A/Gを含む画面を記録してください。`ACC` は静止時およそ1.00Gが目安です。`LAST:` は直前に窓を棄却した理由で、次の静止窓を集計中にも残ります。`WAITING FOR GYRO` はジャイロが新鮮でない状態、`CHECK ACCEL SIGNAL` は加速度の大きさが校正範囲外である状態です。

持続する運動やセンサー欠落を、時間切れだけで強制的にREADYへ進める処理は追加していません。
